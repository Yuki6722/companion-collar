# 伴侣视角 · 可演示原型

> Vibe Coding Camp · Team 2 立项《伴侣视角》的三天交付物。
> 用一张自家客厅照片，展示「人眼 / 犬 / 猫」三种看法，并给出居家环境资源自检清单。

**打开方式**：双击 `index.html` 即可。单文件、离线可用、不需要服务器、不需要头显。

---

## 一、它做什么

| 步骤 | 做什么 |
|---|---|
| ① | 选一张自家照片（或直接用内置样例） |
| ② | 选物种（猫 / 犬）与是否叠加「昏暗环境」亮度示意 |
| ③ | 并排看三种视图：**人眼所见** / **二色觉近似模拟** / **低视角 + 感官叠加** |
| ④ | 按「健康猫科环境五大支柱」自检，得到「还有 N 项值得检查」，可导出分享卡片 |

照片**全程在浏览器本地处理，不上传任何服务器**（纯 canvas 像素操作，没有后端）。

## 二、为什么是这个形态（而不是 VR 头显）

立项文档里把 VR 写成了产品定义的一部分，但研究给出了两条硬约束：

1. **WebXR 在 iOS Safari 全版本不受支持**（caniuse + MDN 双重验证），而宠主主力是手机端的 90 后（42.7%）与 00 后（26.3%）。锁头显 = 锁掉绝大多数受众。
2. **头显的性能门槛**：运动到光子延迟 20–30 ms、90 fps 约 11 ms/帧是基线，掉到 72 fps 即可诱发不适——对三天的新团队是硬风险。

因此保留「以宠物尺度与感官重新看家」这个核心叙事，把「沉浸」从技术指标降级为实现程度问题。完整论证见
[research_宠物视角VR立项_20261002.md](../research_宠物视角VR立项_20261002.md)。

## 三、文件结构

```
companion-perspective/
├─ index.html                  ← 交付物：单文件自包含（science.json 与样例照片已内联）
├─ science.json                ← 唯一数据源：数值 + 来源 URL + 措辞 + 存疑标注
├─ tools/render_reference.py   ← 生成样例照片 / Python 参考实现 / 内联数据进 index.html
├─ assets/samples/             ← 样例照片（示意图样）
│   └─ reference/              ← Python 参考实现的对比图（离线兜底）
└─ README.md
```

## 四、改完数据后怎么重新生成

`index.html` 里有两块标记为 `AUTO-GENERATED` 的内容（science 数据与样例照片 data URI）。**改了 `science.json` 或想换样例照片后，必须重新生成**：

```powershell
cd companion-perspective
& 'C:\Users\ROG\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\python\python.exe' tools\render_reference.py
```

脚本会依次：生成样例照片 → 跑自动断言 → 生成参考对比图 → 把数据内联进 `index.html`。

**为什么必须内联**：`index.html` 可能被以 `file://` 直接打开，此时 `fetch('science.json')` 会被浏览器拦截；而本地 `file://` 图片会「污染」canvas，导致 `getImageData` 抛安全错误。内联成 data URI 后，离线打开也能正常处理照片。

### 换成你们自己的样例照片

把 3 张照片放到 `assets/samples/`，命名覆盖 `sample-livingroom.png` / `sample-multicat.png` / `sample-windowlamp.png`，再跑一次上面的脚本即可。（建议：客厅、多猫家庭、有明显光源三种场景；**必须是自有或已获授权的照片**。）

## 七、兜底方案（按顺序）

1. **现场没网**：`index.html` 单文件离线可用，本地打开即可，照片用内置样例。
2. **照片打不开**（iPhone HEIC 在部分浏览器无法解码）：页面会给出提示，直接点内置样例继续演示。
3. **手机不方便**：用笔记本打开同一个文件，功能完全一致。
4. **全挂了**：`assets/samples/reference/` 里有 Python 版跑出来的静态对比图，直接展示图片也能讲完整个逻辑。

## 十、自动断言（`tools/render_reference.py` 会跑）

| 断言 | 实测 |
|---|---|
| 变换确定性、尺寸一致、值域 0–255 | 通过 |
| 亮度保持（色觉差异 ≠ 亮度差异） | 漂移 0.0% |
| 红绿混淆确实发生 | 红绿距离缩小 55% |
| 犬 / 猫切换有可见差异 | 平均通道差 4.92（阈值 1.5） |

## 十一、科学诚实性（重要）

页面刻意做了以下保留，**答辩时这些是加分项，不是弱点**：

- 色觉是**二色觉近似模拟**（合并中/长波锥体 + 亮度校正），**不是**物种实测光谱响应曲线；犬与猫的差别用「保留锥体光谱偏置」作**参数化示意**。
- **猫的锥细胞数量在来源之间存在冲突**（同一份兽医材料写 3 种，主流文献列二色觉），页面明确标为「来源存在冲突」，不声称具体数量。
- 「低视角」标注为**示意**，不做物理重建的宣称。
- 闪烁演示是**慢放**——普通屏幕无法呈现 70–80 Hz 的真实频率。
- 不做嗅觉模拟（无消费级设备），不做「翻译宠物在说什么」（专业行为咨询师已判定不可靠且可能有害）。
- 措辞纪律：只宣称可视化**可核查的感官参数**，不声称知道猫／狗此刻在想什么（对应动物行为学的「批判性拟人化」讨论）。

所有数值与来源见 `science.json`，页面「科学说明与来源」面板逐条渲染，可点击核对。
