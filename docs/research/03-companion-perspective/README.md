## 一、可演示原型做什么

选一张自家照片（或用内置样例）→ 选猫 / 犬 → 并排看三种视图 → 按「健康猫科环境五大支柱」自检 → 导出分享卡片。

- **① 人眼所见**：原始照片
- **② 二色觉近似模拟**：红沙发与绿植变成同一色系，蓝色保留
- **③ 低视角 + 感官叠加**：裁掉上部、地板占比变大，并叠加同一套色觉变换

外加**感官差异速览**：慢放闪烁示意（人眼约 60 Hz 融合 vs 犬猫 70–80 Hz）、对数刻度听阈对比（人类 31 Hz–8 kHz / 猫 58 Hz–75 kHz / 犬 67 Hz–45 kHz）、猫的视野与暗视觉。

照片**全程在浏览器本地处理，不上传任何服务器**。

### 为什么不做 VR 头显

立项文档里把 VR 写成了产品定义的一部分，但研究给出了两条硬约束：

1. **WebXR 在 iOS Safari 全版本不受支持**（caniuse + MDN 双重验证），而宠主主力是手机端的 90 后（42.7%）与 00 后（26.3%）。锁定头显 = 锁定最小受众。
2. **头显性能门槛**：运动到光子延迟 20–30 ms、90 fps 约 11 ms/帧是基线，掉到 72 fps 即可诱发不适——对三天的新团队是硬风险。

因此保留「以宠物尺度与感官重新看家」这个核心叙事，把「沉浸」从技术指标降级为实现程度问题。完整论证见研究报告。

## 二、研究报告的核心结论

| # | 结论 |
|---|---|
| 1 | **痛点形式是「自认懂、实际读不准」**：PLOS ONE 2026（n=647）证明养犬者识别细微疼痛信号不优于非养犬者；PDSA PAW 2024 显示 95% 猫主人自认已懂如何提供合适环境，但 42% 的英国猫与另一只猫同住、约 180 万只猫可能因同居伙伴应激 |
| 2 | **机制有效但已被占位**：iStrayPaws（ACM VRST 2024）证明第一人称动物视角 VR 显著提升共情，但对象是流浪动物；且 2025–2026 已涌现一批「非人类具身」作品，赛道正在变窄 |
| 3 | **行业最热的声音翻译路线已被专业方否定**：猫行为咨询师指出猫焦虑的发声与发情/回应主人极相似，标准化翻译易造成危险误判 |
| 4 | **差异化空位**在「家养宠物 + 饲主自家环境 + 理解而非同情」 |

研究报告置信度 **80%**，并明确列出了未解决的缺口（含核心因果链尚无研究直接验证）。

## 四、科学诚实性（重要）

原型刻意做了以下保留，**答辩时这些是加分项，不是弱点**：

- 色觉是**二色觉近似模拟**（合并中/长波锥体 + 亮度校正），不是物种实测光谱响应曲线；犬与猫的差别用「保留锥体光谱偏置」作**参数化示意**。
- **猫的锥细胞数量在来源之间存在冲突**（同一份兽医材料写 3 种，主流文献列二色觉），页面明确标注，不声称具体数量。
- 「低视角」标注为**示意**，不做物理重建的宣称。
- 闪烁演示是**慢放**——普通屏幕无法呈现 70–80 Hz 的真实频率。
- 不做嗅觉模拟（无消费级设备），不做「翻译宠物在说什么」（专业行为咨询师已判定不可靠且可能有害）。
- 措辞纪律：只宣称可视化**可核查的感官参数**，不声称知道猫／狗此刻在想什么（对应动物行为学的「批判性拟人化」讨论）。

所有数值与来源见 `docs/science.json`，原型页面的「科学说明与来源」面板逐条渲染，可点击核对。

## 五、本地运行与重新生成

**原型**：直接打开 `index.html` 即可（单文件、离线可用、无需服务器）。

**改了科学数据或想换样例照片后**，需要重新生成（`index.html` 里有两块 `AUTO-GENERATED` 内容）：

```powershell
python docs/tools/render_reference.py     # 需先 cd 到原型目录，按脚本内的相对路径调整
```

脚本会依次：生成样例照片 → 跑自动断言（确定性 / 亮度保持 / 红绿混淆 / 犬猫差异）→ 生成参考对比图 → 把数据内联进 `index.html`。

**研究报告网页**由 Markdown 生成，生成脚本见本地工作目录的 `build_html_report.py`。
