# 11 · 柴犬模型与狗的行为

> 在 `#/dog`（[10 号文档](10-dog-home-and-yard.md) 的房间 + 院子）里放一只**柴犬**，
> 让它自己活动，并支持两个手动触发的负面突发演示。

---

## 1. 四层分工（这是本页最重要的一张表）

「倒着走」「从一个位置闪到另一个位置」这类故障，几乎都来自**职责越界**：
动画顺手改了世界位置、或者场景顺手改了姿态。所以这次先把边界钉死，再写实现。

| 层 | 文件 | 只许做什么 | **绝不许做什么** |
|---|---|---|---|
| 几何 | `dog/dog-model.ts` | 关节与网格装配 | 不做任何动画、不写任何变换 |
| 姿态 | `dog/dog-controller.ts` | 只写 `body` 及其子节点（四肢、头颈、尾、耳、颌） | **绝不碰 `root`** |
| 世界 | `dog/dog-behavior.ts` | 只写 `root` 的**位置与朝向** | 绝不写关节角度 |
| 语义 | `packages/core/src/behavior/dog.ts` | 只谈「什么活动、多长时间、去哪个锚点」 | 不含任何米制坐标 |

契约是 `dog/dog-rig.ts` 里的 `DogRig` 接口：模型与控制器各自对它编程，
任何一个关节漏配都会在 `pnpm typecheck` 当场暴露 —— 而不是等到画面上"看着有点不对"。

## 2. 柴犬（`dog-model.ts`）

程序化建模，**不用扫描模型**：Poly Haven 的 CC0 库里没有活体犬，而可下载的写实犬模型
来源与授权都不可核实（与猫版同一条理由）。代价如实写明：**写实比例与毛色，但不是照片级扫描**。

验收特征逐条对应到几何：

| 特征 | 实现 |
|---|---|
| 圆润可爱 | 筒状躯干（柴犬不是细腰猎犬）+ 短四肢 + 圆厚爪子 |
| 立耳 | 三角耳 + 浅色内耳，可绕 Z 压平（情绪）、绕 X 前倾（警觉） |
| 卷曲蓬松尾巴 | **5 段**，从尾根明显上翘再向前卷成环，比躯干更粗壮 |
| 短而顺滑双层毛 | 「底毛深 + 上毛浅」分区：赤色背毛，白色腹毛/胸毛/四肢内侧 |
| 面部轮廓干净柔和 | 短吻 + **饱满脸颊**（`cheekL/R`，柴犬"棉花糖"感的来源）+ 浅色吻部（白口罩） |
| 面部细节 | **眉点**（`browL/R` 浅色圆点，柴犬表情读得出来的关键）+ 鼻头 + 可动下颌 + 舌头 |

体尺在 `SHIBA_METRICS` 里具名给出（肩高 / 体长 / 头顶高 / 躯干中心高），
控制器与自检读同一份 —— 不靠"看着差不多"。

**项圈**（本项目的产品形态）挂在 `body` 上而不是呼吸件上：6 个部件
（带体 / 电子仓 / 双 ECG 电极 / 颈腹侧热敏电阻 / 前端摄像头），与猫版一致，默认可见。

## 3. 运动：为什么这里不可能"倒着走 / 瞬移"

用户的两条硬要求是**渲染层的事实**，而沙箱里跑不了浏览器（`AGENTS.md` §6），
没法靠看画面验证。做法是把它做成**结构上的不可能**，再用一个离线审计把它钉住。

`dog/dog-nav.ts` 只有三条规则，全部是纯数学：

1. **一切移动都走节点图**。31 个节点是被核对过的空地，33 条边是被核对过的走廊。
   狗只能在边上走 —— 于是"穿墙""穿过沙发"在**数据层**就不成立。
   通往院子的边**只有一条**（穿过推拉门开着的那一格），由审计断言把守。

2. **朝向恒等于前进方向**。每帧先按上限 `MAX_TURN_RATE` 转头逼近路径切线，
   然后按对齐度 `cos(朝向 − 切线)` 决定放行多少位移；对齐度 ≤ `ALIGN_DEADBAND`（0.2）
   时**位移为 0，原地转身**。于是 `cos(朝向, 位移方向) > 0.19` 恒成立：倒着走在数学上不可能。
   而"先转过来再迈步"恰好也是真狗的做法。

3. **位移上限 = 速度 × 真实帧时**，没有任何捷径分支。

外加一条时间纪律（猫版踩过的坑）：**位移按真实秒推进，不按时间线秒**。
运行时先把该走的路按 `距离 / 速度` 算成"真实需要几秒"，再让这一段在真实时间里占这么久；
时间线秒只决定"这一段的语义长度"。于是**走不到就一定会等**，而不是压缩时间把路走完。
每段分「走过去」与「做这件事」两阶段，演示时钟在段内线性映射 —— 时钟不跳、时间线不漂。

### 3.1 机械证据：`scripts/check-dog-motion.mjs`
按 60 Hz 逐帧模拟 **67 条路线 × 2 档速度**，20 项断言：

| 组 | 断言 | 结果 |
|---|---|---|
| 1 | 节点/边合法 · 15 个行为锚点都有对应节点 · 全图从玄关可达 · **室内 14 个节点 → 院子 17 个节点全部经过推拉门那一格** | ✓ |
| 2 | 每条边的每个采样点都离实体 ≥ 5 cm（狗自己的软垫/食盆豁免） | ✓ 最窄 0.065 m |
| 3 | **A 位移 ≤ 速度×帧时**（最大比值 1.0000）· **B 从不倒着走**（逐帧 `cos > 0.19`）· C 朝向变化 ≤ 转头速率上限 · 全部在有限时间内到达 · 行进途中不穿实体 | ✓ |
| 4 | 吃 / 喝 / 排泄 / 奔跑 / 回窝各有去处且路程在 1–40 m · 出院子必须跨过北墙 | ✓ |

审计在本轮**真的抓到了 5 处错误**并已修正（这是它值得存在的直接证据）：

1. `north → bed-main` 的直连边横穿北窗下的绿植（72 个采样点净距 0）→ 改为绕 `north-west`；
2. `path-d → meadow` 的直线离池边置石只有 0.126 m → 移动 meadow 节点；
3. `path-c → lounge-a` 的草坪对角线压到 2 号草坪灯 → 删掉这条捷径；
4. `lounge → meadow-east` 的对角线穿过休闲躺椅 → 删掉；
5. `north-west → bedroom` 穿过狗自己的床边软垫 → 插入 `bedroom-east` 绕行点。

另外它抓出一条**设计问题**：只要求 `cos > 0` 时，会出现"朝向差 89°、横向一点点蹭过去"的帧 ——
数学上确实没倒着走，画面上却是横移。因此补了 `ALIGN_DEADBAND`，断言也随之收紧到 `cos > 0.19`。

浏览器里另有一个**位移探针**（`?probe=3000` 或 `window.__dogScene.probe('3000')`）：
记录逐帧位置与朝向，算出最大瞬时速度、最小前向余弦、不同位置数与总位移。
二者测的是同一件事，一个测纯函数、一个测实跑。

### 3.2 姿态审计：`scripts/check-dog-pose.mjs`（76 项）

运动审计读不到模型，所以它拦不住"狗趴下时前爪插进地板里"。因此另加一个门禁：
在 Node 里给 `document.createElement('canvas')` 装一个**最小替身**（模型要用 2D 画布程序化生成毛贴图），
把柴犬与控制器真跑起来，逐姿态量四只**爪底**的世界高度。

它在本轮**真的抓到了一次严重故障**，而且抓到的是两层错误：

1. **穿地**：低姿态（趴卧 / 睡 / 喝水 / 嗅闻 / 玩耍 / 排泄 / 坐）把躯干压到 0.13–0.24 m，
   而前肢长 0.29 m —— 膝角不折够，前爪最深**插进地板 15 cm**。
   修法不是逐个调姿态表（每加一个姿态就要重算一遍），而是在控制器里加一道**运行时兜底**：
   量出爪底高度，不够就二分求"刚好够到地面的最小折角"（7 步收敛到 < 1 mm）。
   用二分而不是"按缺口逐步加角"，是因为腿接近伸直时 `d(爪高)/d(膝角) ≈ L2·sin(h+k)` 趋近 0 ——
   逐步迭代在 `sit` 上四步只修掉 1 cm（残留 2.5 cm）。
2. **量错了地方**：兜底加完还剩 2 cm 残差，一直被当成"姿态标定问题"。真正的原因是
   `paw.getWorldPosition()` 给的是**爪网格的原点**，而柴犬的爪子是半径约 2 cm 的厚球 ——
   拿原点当"爪底"，所有高度判定整体差 2 cm（站姿被误判成浮空 2 cm）。
   改成从几何包围盒读"原点 → 爪底"的偏移量之后，**当时的 14 种姿态 × 四只爪底**全部落在容差 4 mm 上，
   步态三个完整循环内的逐帧最低值也都是 4.0–4.7 mm。

> 这一条值得单独记住：**"量错了"比"没量"更危险** —— 它会让后续所有调参都朝着错误的方向使劲。
> 两次都靠"把数字打出来看"才发现，所以这个审计是**把数字打出来**，不是只报通过/失败。

## 4. 行为（`packages/core/src/behavior/dog.ts`）

「共用机制、分开参数」：猫的行为层一行未改，狗自带一套词汇与权重。

**活动**（第九轮起为 16 种）：`resting` / `sleeping` / `walking` / `trotting` / `running` / `sniffing` /
`drinking` / `eating` / `playing` / `eliminating` / `sitting` / `alerting`。

权重按**当日时刻**变化（狗的作息与猫不同，因此自带一份节律函数而不是复用 `RHYTHM_DEFS` ——
混用一套权重等于两套参数漂移）：白天走动/嗅闻/警觉权重高，夜间 `sleeping` 最高；
`running` 只在院子可达时出现且权重低（短时冲刺）。

**两条硬约束**（由单测钉住）：`eliminating` 只能落在 `elimination` 锚点；吃喝各自落到自己的锚点。
时间线的不变量与猫版一致：区间**首尾相接、无空洞无重叠、恰好铺满全天**，同种子完全确定。

## 5. 两个负面突发（手动触发）

| | 时相 | 动作 |
|---|---|---|
| **抽搐** | 先兆 1.5 s → 强直 4 s → 阵挛 7 s → 恢复 2.5 s（共 **15 真实秒**） | 僵住/耳后压 → 全身僵直侧倾 → 高频抖动 + 四肢划水 + 下颌开合 → 逐渐停止、侧卧、呼吸变深 |
| **呕吐** | 干呕 3.0 s → 呕出 1.2 s → 恢复 3.0 s（共 **7.2 真实秒**） | 腹部反复收缩、拱背 → 头更低、下颌大张、前倾 → 舔嘴回正 |

时相划分写在 `DOG_INCIDENT_DEFS` 里（core），姿态实现在控制器里 —— 一边是"什么时候发生什么"，
一边是"关节怎么摆"。**多时相而不是持续抖动**是验收重点：只有时相才能让"发作"读起来像发作。

⚠️ 两条时长必须分开看：时间线上 `seizure.durationS = 30` 是**演示秒**（12× 下只有 2.5 真实秒），
而动画需要 15 真实秒 —— 直接拿演示秒当段落长度，抽搐会在先兆期就被切掉。
因此运行时把这一段**撑到动画走完**（`incidentRealSeconds()`），代价只是这一段演示时钟走得更慢
（12× → 2×），换来的是"点了抽搐真的看得到全过程"。这条对齐是集成时才发现的坑。

触发路径与猫版同一条纪律：由 `screens/dog.ts` **重建带注入的时间线**再交给场景，
而不是让场景内部另建一条 —— 否则画面与数据会变成两条时间线。

> **措辞边界**：两个按钮只描述**动作**，不命名任何状况；边界句与转诊路径来自 core 的
> `DOG_INCIDENT_BOUNDARY_NOTE` / `DOG_INCIDENT_REFERRAL_NOTE`，UI 层不得改写。
> 本项目的数据全部为仿真，任何读数都不构成兽医诊断依据（`AGENTS.md` §3.4）。

### 5.1 第四轮反馈之后的三条硬化

| 要求 | 做法 | 机器断言 |
|---|---|---|
| **抽搐要有明显的原地抖动** | 抖动拆成**上下**与**横向**两个独立幅度（`tremorAmp` / `tremorRollAmp`）。只放大上下位移会做成"整只狗在弹跳"，而阵挛是躯干左右抖。阵挛期取上下 ~10 cm + 侧倾摆幅 ~23°，两个不同频率叠加以免读成规律振荡 | 阵挛期窗口内躯干上下摆幅 ≥ 5 cm、侧倾摆幅 ≥ 20°（`check:dog-pose`） |
| **呕吐要吐出东西，10 秒后消失** | 控制器给出一次性事件 `consumeVomitEmit()`（干呕期结束时返回一次 true），场景在**狗嘴前方**按当前朝向落一团不规则呕吐物，**10 真实秒**后连同几何一起清掉 | 一次呕吐只触发一次、发生在干呕之后、重复点击会再触发一次、抽搐不会误触发。（10 秒消失与落点需要看画面） |
| **两个突发原地发生，不许跑开** | 突发段**完全不寻路**：路线就是"当前这一点"，`travelS = 0`，到位与转身直接置真；点击时把新时间线的起点接在 `atS`（而不是 `atS - 1`），否则会先落回上一段、朝那个锚点走一秒再发作 | 运行时逐帧记账 `incidentDrift()`，徽章里的 `dogIncidentDrift` **恒应为 0.000** |

> 关于"10 真实秒"：演示倍率是 12×，若按演示秒算，10 演示秒 = 0.83 真实秒 —— 东西刚落地就没了。
> 这类**给人看的效果**一律用真实秒计时，与行为时间线的倍率解耦。

### 5.2 两个动态机位

`CAMERA_PRESETS` 是**静态世界坐标表**，放不下这两个 —— 它们的坐标每帧才算得出来：

| 机位 | 做法 |
|---|---|
| **狗特写** `dog-follow` | 相机挂在狗的**斜后方**（按运行时给的朝向每帧重算）。为什么按朝向算：手写固定偏移在狗转身后会钻进家具里（猫版踩过）。看向它的胸口，距离 1.25 m |
| **狗视角（项圈相机）** `dog-cam` | 相机站在项圈前端那颗镜头（`collar-camera`）上，朝狗的 `heading` 略向下看；**渲染时把狗整个隐藏** —— 真实项圈相机也拍不到自己的后脑勺。朝向取 `heading` 而不是镜头网格自身的朝向：镜头是个旋转过的圆柱，它的局部轴与"狗往哪看"并不一致 |

`check:dog-pose` 断言 `collar-camera` 这个名字存在、且站姿时它在颈部高度（实测 0.330 m）——
改名会被门禁拦住，不会退化成"相机一动不动"。

> ⚠️ 与硬约束 §3 一致：项圈相机是**环境影像记录**，不是"狗眼中的世界"。
> 帧率、视野、以及嗅觉通道都不等价，UI 的 hint 里如实写了这一句。

## 6. App 预览（第八轮：猫版那台 iPhone 搬到狗版，指标按狗的标准）

右栏的 iPhone 机模**与猫版是同一个组件**（`ui/app-phone.ts`），四个模块（实时 / 事件流 / 健康 / 档案）
的**结构、刷新纪律、变红与弹窗的判据全部复用**；差异只来自构造时注入的一套**物种词表**
（`ui/app-vocab.ts` 的 `AppSpeciesVocab`）。这就是仓库那条决策「共用机制、分开参数」在 UI 层的兑现。

### 6.1 词表参数化

| | 猫（缺省） | 狗 |
|---|---|---|
| `vocab` | `CAT_APP_VOCAB`（**不传就是它**） | `DOG_APP_VOCAB` |
| 品种下拉 | `CAT_BREEDS`（12） | `DOG_BREEDS`（15，吉娃娃 → 大丹，含**柴犬 40 cm / 10 kg**） |
| 活动标签 | `eliminating: '用猫砂盆'` | `eliminating: '在院内排泄'` |
| 年龄档 | 幼猫 / 成猫 / 老年猫 | 幼犬 / 成犬 / 老年犬 |
| 体型档 | `cat-small` / `cat-standard` / `cat-large` | `toy` / `small` / `medium` / `large` / `giant` |
| 锚点标签 | `CAT_ANCHOR_LABELS` | `DOG_ANCHOR_LABELS` |
| 突发 | `INCIDENT_DEFS` | `DOG_INCIDENT_DEFS`（抽搐 / 呕吐） |

**默认值就是猫的那套**，这是硬要求：`screens/home.ts` **一行都没有改**，猫版画面逐字不变。
（这条不是靠肉眼确认的：重构时用 `git show HEAD:` 取出重构前的原文，把 4 张标签表与 5 句文案
在 Node 里真求值后逐项比对 —— 97/97 相等。校验器用完即删。）

`AppPhone` 也不再 `import` 猫场景的 `BehaviorStatus` —— 它在本文件内定义一个**结构化最小接口**，
猫的 `BehaviorStatus` 与狗的 `DogBehaviorStatus` 都能结构兼容地传进来（UI 层不该依赖某个具体物种的场景实现）。
时间线由 `timelineOf()` 统一取（`dogBehaviorTimeline ?? behaviorTimeline`），
于是事件流、次数格、自检计数在狗版也拿到正确的那一条。

> ⚠️ **一处发现的层次问题（本轮只是绕过，没有解决）**：core 的三条面向用户的边界句主语写死了猫
> ——`VITALS_BOUNDARY_NOTE`（"不是对**猫**身体状态的判断"）、`VITALS_SIM_NOTE`（"在**猫**上均未取得验证研究"）、
> `VITAL_ALERT_REFERRAL`（"**公猫**反复蹲砂盆却排不出尿"）。狗版页面与弹窗会直接显示"猫"。
> 本轮的处置是：**猫版直接引用 core 常量**（渲染逐字不变），狗版在 `app-vocab.ts` 里
> **只换主语、否定结构一字不削**。
> 但边界句属于领域政策，**理应住在 core 并按物种参数化**，而不是让 web 层改写 —— 已记入待办。
> 另外 `incidentHints` 挂在实时页那一行的 `title` 上（**不新增文字节点**），这是本轮唯一的追加式 DOM 变化。

### 6.2 指标确实按狗的标准（实测数字）

会话生成器 `baselines()` 本来就有物种分支，但**狗这条路以前从来没被走到过**。
现在 `generateSession()` 按 `profile.species` 分派：狗走 `buildDogTimeline` + `SIM_DOG_ANCHORS`，
`Session` 新增 `dogBehaviorTimeline?: DogBehaviorTimeline`（**`behaviorTimeline` 原样保留**，
不改联合类型 —— 否则猫那一路的每个消费点都要收窄一次）。

同一份种子、各跑 24 小时，实测中位数：

| | 猫（家短毛 4.2 kg / 24 cm） | 柴犬（10 kg / 40 cm） |
|---|---|---|
| 心率 | **174.1 bpm** | **114.7 bpm** |
| 呼吸 | 27.6 /min | 21.5 /min |
| HRV (RMSSD) | 44.8 ms | 69.8 ms |
| 体表温 | 35.7 °C | 35.7 °C |
| 活动词汇 | 11 种（含理毛 / 躲藏 / 上高处 / 抓挠 / 用砂盆） | **12 种**（走动 / 小跑 / 奔跑 / 嗅闻 / 睡眠 / 坐 / 警觉 / 进食 / 玩耍 / 排泄…） |
| 锚点 | 13 个（猫爬架顶 / 砂盆 / 纸箱…） | **15 个**（草坪 / 排泄角 / 院内水盆 / 木平台…） |

> 这几个数是**仿真参数**，不构成任何临床或诊断用途；狗的静息心率就是比猫低、HRV 就是比猫高，
> 单测只钉方向与量级（狗 60–140 bpm、猫 > 狗 × 1.2、狗 HRV > 猫 HRV），**不去编造精确值**。

另外两处必须写下来的决定：
- **狗路径刻意不产出 `elimination-outside-box` 与 `hiding`**：狗没有砂盆、也没有"躲藏"这类活动，
  而行为层把排泄硬约束在院子排泄角 —— 在那里排泄是**它该做的事**，
  记成"越界"等于把正确行为描述成异常。
- **体动键要折一次**：`vitals.ts` 的 `ACTIVITY_MOTION` 是按猫的活动词汇建的，
  所以狗的活动名先经 `vitalsActivityKeyOf()` 折成猫的键（奔跑/玩耍 → playing，嗅闻 → grooming…）
  再取体动量；但 `Sample.activityId` 仍写**狗的原生名**，于是"采样 ↔ 时间线一致"的断言照样成立。
  活动量另有一张狗自己的表 —— 复用猫表会让"走动"拿到理毛档的取值，漂移基线就变成映射的产物。

### 6.3 「实时」页：项圈相机离屏画面

猫版的 POV 离屏渲染已移植到 `dog-scene.ts`（`setPovCanvas` / `povState` / `updatePovFeed`）：
眼睛取**项圈前端镜头网格的世界位置**（颈部姿态由控制器写，这里只读结果），
朝向取运行时的 `heading` 再下俯 8°，节流 8 fps，**渲染这一路时把狗自己隐藏**
（真实项圈相机拍不到自己的后脑勺），尺寸不变就复用渲染目标，`setPovCanvas(null)` 立刻停渲染。

相对猫版有一处**有意的偏差**：绑定时清空平滑状态 —— 解绑期间狗可能已经走到院子另一头，
若首帧仍从旧机位插值，切回「实时」页的第一帧会是"半旧"画面。

### 6.4 单一时间线

狗版页面现在也走**会话作为单一数据源**：场景不再自己生成时间线，而是消费
`session.dogBehaviorTimeline`；点突发时由 `screens/dog.ts` 重建**带注入的会话**，
把新时间线交给场景、把新会话交给 App。于是画面、事件流、手机读数**共用同一条时间轴** ——
这是猫版在 `docs/design/07` 里关掉的那个接缝，狗版从一开始就按同一条纪律写。

## 8. 院子里的自由活动与互动（第九轮）

用户反馈：**"狗在院内只会在石板路上走动，希望它能在院子内任何位置行动或玩耍，多增加一些交互，
比如走到水池边会发生在水池里玩水的动作。"**

### 8.1 病因：不是行为层不想去，是导航图只铺了路面

院子 9.6 × 8.2 m，而院子里的导航节点原本只有 **10 个**，全部落在三条石板路与几个点位上
（`path-a`…`path-d`、`pond-north`、`lounge-a`、`meadow`、`meadow-east`、`elimination`、`yard-water`）。
草坪上一格都没有 —— **"能走的地方"是被图限制住的**，行为层再想让它去草坪也无路可走。

### 8.2 做法：把草坪铺成可走的面

不再手写几十个坐标，而是**确定性生成 + 逐点剔除**：在 `YARD_BOUNDS` 内按约 0.9 m 格距布候选点，
剔除与任何 `kind === 'solid'` 实体（树/灌木/置物石/池塘/躺椅/藤架柱/石灯笼/草坪灯）净距不足的点，
再只在**直线段净距合格**的相邻点之间连边。生成结果照样被门禁逐边校验（门禁读的是编译产物）。

| | 改前 | 改后 |
|---|---|---|
| 导航节点 | 31 | **98** |
| 边 | 33 | **237** |
| 运动审计断言 | 20 | **31** |

新增 7 个**具名互动点位**：`lawn-c/w/e/n`（草坪四向）、`shade-tree`（树下）、`dig-bush`（灌木边）、
`pond-edge`（**紧贴水面的池岸**，玩水用）。

### 8.3 验收：草坪覆盖率是这一轮的机械证据

运动审计新增两条断言，把"能在任何位置行动"变成可证伪的数：

- **覆盖率**：草坪上按 0.5 m 取样 **130 个点**（排掉落在实体上与封死死角里的），
  每一点到最近导航节点的距离 **全部 ≤ 0.7 m，实测最坏 0.595 m**；
- **互动点位可达**：`pond-edge` / `shade-tree` / `dig-bush` / `lawn-c/w/e/n` 各自至少 2 个邻居，
  且从 `deck-in` 出发都可达；
- **决策守卫**：断言 `yard-pond` 具备 `water` 能力且节点列表含 `pond-edge` ——
  防止以后有人把玩水点删掉、用户点名的交互静默失效。

### 8.4 四个新的院子互动

| 活动 | 姿态 | 锚点 | 24 小时出现次数（seed 42） |
|---|---|---|---|
| **玩水** | `water-play`（新） | `yard-pond`、`outdoor-water` | **9** |
| **草地打滚** | `rolling`（新） | `yard-lawn-center`、`yard-lawn-west` | **10** |
| **刨地** | `digging`（新） | `yard-dig` | **7** |
| **晒太阳** | `down`（复用） | `yard-shade`、`yard-lawn-west`、`deck` | **4**（且**只在 07:00–19:59**） |

狗的锚点 15 → **20**，活动 12 → **16**，姿态 14 → **16**。玩水配**水花**视觉：
控制器给一个**反复触发**的事件 `consumeSplashEvent()`（每完成一次扒水动作返回一次，
与一次性呕吐事件不同），场景在狗身前水面生成一小簇水珠 + 一圈扩散水环，约 1 秒后清掉。

> ⚠️ **两个踩到的结构坑，都值得记下来**：
>
> 1. **行进速度不能给 0**。这四个活动是"到点后原地做"，看起来速度该是 0 —— 但那张表同时决定
>    `travelS = 距离 / 速度` 与路径推进的步长。给 0 会让狗**永远走不到锚点**，
>    于是"就地开始玩水"（在厨房里扒水花）。所以它们沿用与 `resting` 同一档的 **0.9 m/s**，
>    "原地做"由运行时在到位后保证。
> 2. **窗口太短会让活动一次都不发生**。引擎把一次选定拆成「走过去（≥10 s）+ 到位后的动作」，
>    窗口 ≤ 40 s 时整段会被记成 walking —— 实测窗口取 12 s 时**打滚一次都没出现过**。
>    所以时长给的是**整段窗口**而不是动作时长，并配了 `STAY_FLOOR_S` 下限。
>    "加了活动但它从来不出现"是静默失效，已由单测钉住（四个活动都必须出现，玩水 ≥ 2 次）。

### 8.5 新增第五道门禁：三张锚点表必须逐字同序

同一个锚点在三个包里各有一份表述（core 的 `DOG_ANCHOR_IDS`、simulator 的 `SIM_DOG_ANCHORS`、
web 的 `DOG_ANCHOR_SPECS`），靠人工同步。core↔simulator 有单测，**web 那一侧原本没有**——
一旦漏一个 id，表现是"时间线让狗去某个锚点、渲染层查不到 → 退到兜底节点 → 狗在莫名其妙的地方做动作"，
而任何单测都不会报错。

所以加了 `scripts/check-dog-anchors.mjs`：从**编译产物**读三张表（dist 里的相对导入链完整，
绕开了 node_modules 的类型剥离限制，见 `AGENTS.md` §5.5.6），比较内容与顺序、
检查锚点→导航节点映射无悬空、并守卫院子互动锚点不被删掉。

> 这个脚本里有一条**如实报告"跳过"**的分支：core 的能力表是刻意放宽的 `readonly string[]`，
> 没有导出可按锚点查的映射，于是能力一致性这一条**这一轮没有真的验过**。
> 把跳过写成 ✓ 就是假证据 —— 所以它打印 `⊘ 跳过` 并说明原因。

### 8.6 手动触发：让这些交互**看得见**

12× 演示时钟下，玩水一天约 9 次 → 平均**每 13 真实分钟**才出现一次。靠"盯着院子等"来验收是不现实的，
所以左栏加了一排按钮（`玩水` / `草地打滚` / `刨地` / `晒太阳`）：点一下就让狗**走过去再做这件事**。

实现纪律：**复用现有的路线机制**（合成一段临时 segment 走 `startSegment` 那条路），
而不是直接改坐标——三条运动学不变量因此照旧成立。锚点挑选也复用 core 的活动定义与
`resolveAnchorNode`，不另写一套。**手动触发不重建会话**（那是突发注入的机制）：
时间线本身不动，手机 App 的数据不受影响。

### 8.7 两处必须记下来的判断

**① 锚点解析要防退化。** `yard-lawn` 的候选从 4 个扩到 64 个之后，"去草坪"几乎总会解析到
**狗正站着的那一格** → `travelS = 0` → 那一段只剩原地动作，画面上是**摆着奔跑姿势不动**。
所以 `resolveAnchorNode` 加了防退化：候选 ≥ 3 时跳过 1.5 m 内的候选，全都太近则取最远；
候选 ≤ 2 的锚点（食盆、木平台、池塘…）行为完全不变。运动审计同步加了一条断言。

**② 圆形障碍被建成了方块 —— 这是本轮的一处已知残留。**
`layout-dog.ts` 的 `circle()` 走到 `rect()`，于是灌木/树干/置石/草坪灯在**斜向上被放大最多 41%**。
后果：院子东北角（点景灌木与围栏之间实际只剩 4 cm 的缝）等约 **14 个采样点 ≈ 3.5 m²** 的草地
达不到 0.30 m 站位净距，因此没有布点、覆盖率断言也不把要求加在它头上 ——
**这是如实处理，不是达标**。要让那几片草地也走得到，正确做法是让圆形占地走**真圆距离**
（现在只有池塘有 `ellipse` 字段），并同步 `check-dog-motion.mjs` 与 `check-layout-dog.mjs` 的距离函数
（审计用的是方块，因此偏保守：只会多报碰撞，不会漏报）。已记入待办。

> 另外记一笔：`check-dog-motion.mjs` 的路线集从"67 条全对全"改成
> **237 条边各走一次 + 关键路线 + 固定种子抽样 48 对**（315 条 × 2 档速度，单次 3.8 s）。
> 每条边与每个节点仍被覆盖 —— 这是为控制运行时间做的**有意的取样**，不是断言放松
> （断言数 20 → 32，反而更多）。

**③ 采样域为空会让覆盖率断言假通过。** 门禁打印了取样点数（130）与被排除的两个计数
（实体上 162 · 不可达 48），这样"取样域空了导致断言恒真"这种失效模式会被看见。
