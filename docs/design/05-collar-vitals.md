## 2. 本阶段唯一的核心判断：**读数与真值必须分开**

如果仿真让「体表温 = 核心温 − 2.7」，那么任何"由体表温推核心温"的算法在评估里都会表现完美——
**那是自证预言，不是验证。**

所以这里有一条硬规矩，写在 `simulator/src/vitals.ts` 的头部并被回归测试钉住：

> **体表温的生成输入里没有核心温。** 它由环境温 + 被毛隔热 + 接触状态 + 自身慢漂决定。
> 「两者无相关」（Kendall τ ≈ −0.01）是被**编码进模型**的结构，不是留给仿真去发现的事实。

实测（`--seed 42 --minutes 1440`，8640 个采样点）：

| 量 | 值 |
|---|---|
| Pearson r（体表温读数 vs 核心温真值） | **−0.018** |
| 线性拟合 R² | **0.0003** |
| 拟合后平均绝对误差 | **0.77 °C** |
| 体表温读数中位 / 核心温真值中位 | 36.02 °C / 38.40 °C |

也就是说：**强行拟合的斜率为负、解释方差为 0、误差接近信号本身的大小。** 这就是"不得换算"的可执行版本。

## 3. 数据流与包归属

```
generateSession()                        [simulator]
  ├─ samples[]：hrBpm / hrvRmssdMs / rrBpm / tempSurfaceC
  │              + readingQuality{valid|motion-artifact|poor-contact|rejected-out-of-range}
  │              + measurementCondition{sleep|resting|active|post-event|clinic}
  │              + motionIndex
  └─ truth.vitals[]：hrTrueBpm / rrTrueBpm / tempCoreC / condition
        │
        └─► core/src/vitals/            [core]
              readings.ts   有效性与可用性（validVitals / summarizeAvailability）
              baseline.ts   按测量条件分层的稳健基线（复用 core/baseline.ts）
              drift.ts      同条件漂移（复用 core/drift.ts 的效应量+置换检验+持续性）
              sleeprr.ts    睡眠呼吸频率（阈值取自登记表，不在实现里写死）
              params.ts     证据登记表 + 操作化常量
                    │
                    └─► apps/web：#/vitals（读数 vs 真值 + 可用性 + 规格）
```

**为什么不把急性流塞进 `samples`**：生理采样是 10 s 粒度，而急性动作需要秒级特征；
且 24 h 会话已有 8640 个采样点，再把秒级流并进去会让会话 JSON 从数百 KB 涨到数 MB。
急性/动作那一层是**另一条工作线**，本阶段只做读数层与它的边界。

## 4. 关键决策记录（都是"为什么"，实现细节见代码）

| 决策 | 为什么 |
|---|---|
| `tempC` 从 `Sample` 删除，改名 `tempSurfaceC`；核心温进 `truth.vitals` | 原字段其实是一个"干净的核心温"，留着一定会被当成项圈能测的量 |
| 无效窗口**保留坏值 + 原因**，但算法层只走 `validVitals()` | 真机上设备确实会吐数。"不可用"必须是一等数据，才能被划线展示；藏起来或当读数用都是错的 |
| 基线按条件分层；跨条件漂移直接 `degraded` | 诊室读数与居家读数差一倍以上，不分层测出来的是"换了地方" |
| 呼吸门限（0.25）远严于心率门限（0.6） | 颈部呼吸信号弱，体动是同一量级的干扰源 |
| **项圈移位**作为与体动无关的第二条失效通道 | 若失效只由体动驱动，仿真会给出过于乐观的可用率；而"休息时读数一定准"恰恰没有被验证 |
| 「多次测量 >30」按**独立睡眠时段**计数 | 共识原文没有定义"多次"；把连续 10 秒采样当作多次会严重高估。取值 3 是操作化常量，并在界面写明 |
| 睡眠呼吸频率用**中位数**而不是原文的均值 | 单次伪迹不该抬高判断；这一偏离在界面里明说 |
| `vet-visit` 场景**只改读数、不改真值** | 为了把"情境偏移"与"生理变化"分离。真实诊室里两者同时存在（应激本身也会抬高心率），因此这是**教学用的分离演示**，不是对真实诊室的仿真 |

## 5. 界面：`#/vitals`

1. **三通道卡**：最近一个可用读数的值 / 时间 / 条件 / 质量；可用率条；主要失效原因；验证状态（`unverified`）；
2. **读数 vs 真值折线**（HR / RR / 体表温各一张）：同一个会话的两条线，差距一目了然；
3. **可用性报告**：每通道"报出比例 vs 可用比例"、失效原因分布、测量条件分布；
4. **睡眠呼吸频率**：中位数、独立时段数、超阈值时段数、共识阈值与出处、要请主人回答的四个问题；
5. **项圈规格卡**：重量预算 vs 在售同类、三通道选型、触须无干涉区硬约束；
6. **证据登记表 + 操作化常量**：每个数字都能追到来源；每个我们自己拍的数字都写明理由。

常驻边界句与仿真声明来自 `@camp/core`（`VITALS_BOUNDARY_NOTE` / `VITALS_SIM_NOTE`），界面不另写一套。

**3D 侧**：`?collar=on` 显示项圈硬件，`?collar=zone` 同时标出触须无干涉区；
HUD 的「图层与画质」里有两个独立开关（讲解时经常需要只看其中之一）。

## 6. 测试

`packages/core/test/vitals.test.ts`（20 项）与 `packages/simulator/test/vitals.test.ts`（9 项）覆盖：

| 断言 | 为什么它值得占一个测试位置 |
|---|---|
| `unverified` 参数无值且展示文本不含数字；`disputed` 必须是二元区间 | 证据政策的执行点 |
| 项圈三通道的验证状态一律 `unverified` | 本阶段最不能含糊的一条 |
| 无效窗口不提供可用读数，但坏值可展示 | 「坏值可见 + 不可用」两个属性都要成立 |
| 把运动伪迹算进基线会撑大离散度 → 所以必须排除 | 伪迹污染基线的后果是"再也测不出真实变化" |
| 条件不一致时必须拦下 | 否则测到的是"换了地方" |
| 体表温与核心温无相关 + 拟合无信息 + 误差很大 | 换算不成立的三重证据 |
| 诊室情境只抬高读数，真值一模一样 | 情境偏移的分离演示 |
| 移位失效与体动无关且**成段**出现 | 防止"只在体动时失效"的过于乐观建模 |
| 三通道都既非全天候可用、也非永久失效 | 两侧都防止过度宣称 |
| 注入抽搐后真值心率与核心温上升 | 与 `docs/research/06` 的 hyperthermia 机制一致 |
| 公共 API 无换算符号 | 用测试守住"刻意不提供"这件事 |

**实测可用率**（`--seed 42 --minutes 1440`，客厅的一天）：心率 **91.1%**、呼吸频率 **83.3%**、体表温 **72.6%**
（失效原因：运动伪迹、接触不良、固件拒收）。睡眠时段占 50.7%，与家猫约 12 小时/天的睡眠一致。

## 8. 边界与明确不做

- 不做诊断、不做治疗建议、不做疾病判定（`AGENTS.md` §3.4）
- 不做核心温换算、不做体温预警、不做血压、不做临床级/医疗级宣称
- 不做能量消耗估算（AJVR 2024 已证伪）
- 不宣称任何真实准确度：三通道在猫上均为 `unverified`
- 不把「睡眠呼吸频率」包装成设备能力：它是唯一有共识阈值的居家协议，但**原始做法是人用眼睛数**；
  设备版本只能提供"同一条件下的相对变化 + 记录"，并附结构化问题与转诊路径

## 9. 后续接缝

1. **真机适配器**：`DeviceAdapter`（`kind: 'collar'`）已是既有接口，真机只需实现它；`readingQuality` 与
   `measurementCondition` 是必须由设备侧提供的字段（设备不给，界面就无法区分"没测到"与"没发生"）。
2. **体表温裁决实验**：见 `docs/hardware/01-collar-spec.md` §4.2——这是唯一能自己裁决 `disputed` 的低成本实验。
3. **动作/急性层**：与读数层共用同一条行为时间线；读数层只负责"相对自身基线的时间演化"，
   不负责"刚才发生了什么动作"。
4. **多猫归属**：仍未验证，界面在有第二只猫时必须标注"本事件无法归属到个体"。
