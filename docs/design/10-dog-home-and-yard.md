# 10 · 狗的生活场景（房间 + 院子）

> 新增一屏：`#/dog`。**猫版 `#/home` 原样保留** —— 两个场景各自成立、可来回对照。
> 本页记录的是「为什么这样建模」，以及**这个场景能被机械核对到什么程度**。

---

## 1. 本轮范围（用户明确划定的两条边界）

| 用户选择 | 落地方式 |
|---|---|
| **新增独立页面**，猫版不动 | 新增 `#/dog` 路由 + `screens/dog.ts` + `dog-scene.ts`；猫版的 `scene.ts` / `layout.ts` 只做了一处纯搬运式重构（见 §7） |
| **本轮不做狗本体** | 场景里没有犬模型、没有行为控制器、没有 POV 离屏渲染。交付物是**房间 + 院子 + 狗的用品**这件事本身 |

场景的其余要求：写实（不做卡通）· 温暖日系 · 开放式厨房 / 电视 / 沙发 / 床铺 / 柜子 ·
狗的食盆水盆与柔软垫子 · 院子里有草地 / 树 / 花 / 灌木 / 休闲躺椅与小桌 / 石板路 / 小池塘 ·
并且**比猫版更大**。

### 2.2 墙体与洞口

| 墙 | 位置 | 洞口 |
|---|---|---|
| 北（朝院子） | z = −3.5 | 推拉玻璃门 4.2 × 2.4 m（**西端留 1.05 m 开着**）+ 窗 2.2 × 1.4 m（窗台 0.8） |
| 南（入户 + 厨房） | z = +3.5 | 入户门 0.95 × 2.1 m |
| 西（床与衣柜） | x = −4.8 | 卧室窗 2.0 × 1.35 m（窗台 0.75） |
| 东（电视墙） | x = +4.8 | 高窗 1.4 × 1.05 m（窗台 1.15） |

四扇推拉门的分轨：轨 A 在室外侧、轨 B 在室内侧各挂两扇；把**西端那一扇**沿轨推东一格
（轨 A 的这一格本来是空的，因为它的邻位是轨 B 的板），西端就留下 `SLIDING_DOOR_OPEN`
那一格洞。这是推拉门真实的工作方式。**开门位置与主通道是绑定的**：`TRAFFIC_PATH`
必须从这一格穿出屋，`check-layout-dog.mjs` 有一条断言专门盯这件事（玻璃不是 solid 占地，
不绑的话「通道横穿玻璃」这种错没有任何其它检查能发现）。

置物架夹住只剩 0.45 m 缝 —— 与其硬塞，不如留白（日式陈设靠空来衬）。

> **已移除：天花板的四道露明木梁**（用户看过画面后要求去掉）。
> 第一版在 y = 2.94 处横了 4 道木梁（z = −2.3 / −0.8 / 0.7 / 2.2），当装饰性的结构语言用。

> 想要结构语言，北墙的木格栅与木质家具已经足够；`buildFloorAndCeiling()` 现在只剩地板与天花板两片。

## 4. 狗的用品（4 处 + 1 个挂钩）

| 用品 | 位置 | 为什么在这儿 |
|---|---|---|
| 食盆 + 水盆（抬高的木托架 + 防滑垫） | 东墙 x = 4.32，z = −1.15（电视柜与置物架之间的凹位） | 不在主通道上，但视线随时可达 |
| 院内水盆 | 木平台东端 (3.35, −4.25) | 出门就能喝，且不挡在门口正中 |
| 软垫（日光位） | 北墙窗下 (−2.55, −2.85) | 北窗下的日光位；动物自己会挑这种地方躺 |
| 软垫（床边） | 卧室床边 (−1.85, −1.35) | 贴着床沿，长边顺着床（转 90°），不占床头过道 |
| 玩具篮 | 北墙窗下西侧 (−3.75, −3.05) | 与软垫同一区，取用动线短 |
| 牵引绳 + 项圈挂钩 | 入户门东侧的南墙 x = 4.45，y = 1.4 | 出门前拿绳、进门后挂回 —— 唯一能把狗的用品和人的动线绑在一起的位置 |

> **关于「食盆垫高」**：本项目只声称两件可核查的事 —— 碗不会在地板上滑动、
> 拖地时能整块端走。抬高进食对健康的影响在文献里是有争议的，因此**不作任何健康表述**
> （见 [`02-evidence-policy.md`](02-evidence-policy.md)）。

## 5. 院子

| 要素 | 实现要点 |
|---|---|
| 绿色草地 | `ShapeGeometry` **带池塘洞**（不是一块盖住池塘的方板）——否则任何低机位都会露馅。UV 是形状坐标（米），故平铺次数传 `1/1.8` |
| 小池塘 | 椭圆 2.7 × 2.1 m，位于草坪洞里：池壁（开口圆柱，材质双面）+ 池底 + 水面（**低于草坪 0.12 m**）+ 34 块岸边压顶石 + 7 片睡莲 + 42 株水生植物 + 3 块置石 |
| 石板路 | 3 条折线，每 0.62 m 一块，逐块错开角度 / 尺寸 / 横向偏移（等距同向会读成"斑马线"） |
| 树木 | 4 棵：2 棵大树（西侧 / 东北角）+ 1 棵**红枫**（西北角）+ 1 棵小乔木；每棵 = 树干 + 3 根主枝 + 5–7 个不规则树冠团块 |
| 灌木丛 | 9 丛绿篱（北侧一排）+ 4 丛点景 |
| 休闲躺椅 + 小桌 | 木条躺椅（9 条座面 + 7 条靠背 + 扶手 + 搭在椅背的毛巾）· 圆桌（3 条斜腿 + 杯子 + 书） |
| 藤架 | 4 根立柱（**位置即 `PERGOLA_POSTS`，审计用同一组点**）+ 2 根主梁 + 9 条横条 |
| 其他 | 砾石地坪（含木压边）· 石灯笼 · 4 盏草坪灯 · 280 m 见方的远景地面（否则房子会"悬在天上"） |

> **已移除：花坛与花丛**（用户看过画面后要求去掉）。第一版做了 3 处翻过的土面 + 82 朵程序化花
> （茎 + 可着色的花冠，四种颜色各一个实例网格）。问题不在数量而在**读法**：
> 低多边形的花瓣团在写实尺度的院子里不会读成花，只会读成一片彩色碎屑，
> 反而把"写实"这条基调拉垮。
> 因此本轮把 `FLOWER_BEDS`（布局）、`buildFlowerBeds`（建模）、四种 `bloom*` 与 `soil`
> 材质（材质库）一并删净，**不留没人用的分支**；`scripts/check-layout-dog.mjs` 里留了一条
> **决策守卫**断言，让"重新加回来"必须是一次显式决定。
> 空出来的三处在画面上就是草坪 —— 没有任何残留的土面或半截花茎。

## 6. 视觉实现上的四个关键取舍

1. **娃娃屋剖视**：墙是**单面平面**、法线朝屋内，天花板单面朝下。于是相机在屋外能直接看进屋里，
   不需要任何遮挡剔除逻辑；俯视时天花板自动不可见。
   ⚠️ 这也是墙**不能**改用薄盒体的原因 —— 盒体有外表面，从屋外看就是一面实墙。

2. **只给朝院子的那一面加外墙皮**。站在院子里往南看需要一面真墙，而娃娃屋剖视要求
   近侧墙能被看穿 —— 这两件事对**近侧墙**冲突，对**远侧墙**不冲突：
   而朝院子那一面恰好永远是全景机位的远侧（相机在南边俯视时，北墙外皮法线朝北、
   背对相机，自动被背面剔除）。代价如实写明：把相机绕到院子以北回头看，看到的是**外立面**
   而不是剖面 —— 这是刻意选择的行为，且随时可用 HUD 的「朝院子的外墙」开关切回剖视。

3. **成片重复的东西一律实例化**：栅栏竖板、草簇（260）、花（82 × 2）、池边卵石（34）、
   睡莲（7）、水生植物（42）、树冠团块（23）、灌木叶球（39）、栅栏立柱（16）。
   散布全部来自**固定种子**的 PRNG —— 同一版代码每次打开草簇位置完全一致，
   否则「截图核对」这件事失去意义。

4. **洞口框体做成墙厚**（`T + 0.04`、居中放在墙厚中央）：墙是零厚度平面，
   洞口需要"洞壁"；框体自己把洞壁填满，否则从侧一点的角度看过去，
   窗洞两侧会露出两道直通屋外的缝。

## 7. 与猫版共用什么、分开什么

| | 共用 | 分开 |
|---|---|---|
| 构建 | three + 无打包器 + import map · `MaterialLibrary`（木地板 / 乳胶漆 / 石材三张 CC0 贴图的外部替换机制）· `HotspotLayer` · 画质档 · `assets.ts`（同一份 4 个 CC0 扫描模型）· `util.ts` | 布局、材质、几何、光照、相机、HUD、屏幕 |
| 材质 | 室外专用材质另起一个 `GardenMaterials`（草坪 / 砾石 / 石板 / 栅栏板条都没有 CC0 对应件，且草坪用的是米制 UV，`MaterialLibrary` 的取整平铺不适用） | —— |
| 参数 | —— | 房间 9.6 × 7.0 × 3.0 vs 7.2 × 5.6 × 2.75；太阳高度角 47° vs 25°；阴影范围 ±13 m vs 半屋 |

**唯一一处对共用代码的改动是纯搬运**：`fitModel()` 从 `scene.ts` 的私有函数提到
`util.ts` 并导出（狗版也要用同一套「按水平最大边定尺度 + 贴地 + 居中」的落位逻辑）。
两份实现迟早会漂移（第二份漏掉贴地就会浮空），所以合并成一份。猫版
`build-room / build-kitchen / build-furniture / build-cat-gear / scene.ts` 的**行为没有变化**。

## 8. 验证

### 8.1 机械门禁（可在沙箱内跑）

```bash
pnpm typecheck                                    # 3/3 通过（含 erasableSyntaxOnly）
node scripts/check-claims.mjs                     # 措辞门禁通过
node scripts/build-web.mjs                        # 构建 192 个文件
node scripts/check-layout-dog.mjs                 # 布局审计 32 项全通过
```

`scripts/check-layout-dog.mjs` 是本轮补上的关键一环：**沙箱不允许 agent 启动浏览器**
（见 `AGENTS.md` §6），「家具压在墙上」「狗的东西摆在过道上」「树长在池塘里」这三类错误
无法靠肉眼发现，只能对布局数据做机械判定。它读的是建模代码读的**同一份** `layout-dog.ts`，
因此断言真的约束了画面里的摆放：

| 组 | 断言 |
|---|---|
| 1 | 用户点名的 22 项要素都在 `PROGRAM` 里 |
| 2 | 52 个实心占地两两不重叠（同组除外：绿篱是一排灌木、藤架是四根柱）· 无实体落在池塘水面里 |
| 3 | 60 个占地都在自己的区域内（不穿墙、不出院）· 室内没有任何物件穿过天花板 |
| 4 | 4 面墙的洞口都在墙内、不重叠、留足墙垛 · 推拉门开着的那一格宽于 0.9 m |
| 5 | 室内主通道 + 3 条院内小径**全程净距 ≥ 0.05 m** · **主通道从推拉门开着的那一格穿出屋外** |
| 6 | 草地 / 树 / 灌木 / 石板路 / 躺椅 / 小桌 / 池塘 / 置石逐项存在 · **花坛与花丛已移除（决策守卫）** |
| 7 | 狗的用品都在室内且离主通道 1.6 m 以上 · 两张软垫相距 > 1.2 m · 院内另有一个水盆 |

审计在本轮**真的抓到了 3 处错误**并已修正（这是它值得存在的直接证据）：
`tree-b / tree-c / tree-d` 的树干分别与 `bush-c / boulder-0 / bush-d` 重叠、
`bush-c` 越出院墙 0.07 m、`path-pond` 离 `boulder-2` 只有 0.033 m。

## 9. 已知边界与未做

- **不作任何关于宠物的判断**。这一屏是场景建模：它不说这个布置"对狗更好"，
  也不对宠物的感受或健康作任何表述（与本仓库其他屏同一条证据纪律）。
- **没有犬模型**（本轮用户明确选择）。`DogHomeScene` 因此没有控制器、没有行为运行时、
  没有 POV 离屏渲染 —— 它比 `HomeScene` 薄得多，这不是偷工，是范围。
- **没有昼夜与天气**。太阳固定为西北偏北 47°，水面涟漪是唯一的动态元素。
- **没有用户自助编辑布局**（猫版第三阶段的候选仍未做）。
- **色卡与观感未做人工逐张核对**：程序化贴图（草地 / 砾石 / 石板 / 树皮 / 树叶 / 栅栏板条）
  是按"写实观感"的目标参数调的，但没有对着参考图逐个校准过。
