# 07 · 场景页布局与 App 预览（iPhone 机模）

> **状态**：已实现。typecheck 3/3、构建 168 个文件、措辞门禁通过；`?debug=1&auto=1` 的自检序列已覆盖
> App 预览的收起/展开、页签切换与"突发期间读数被标为不可用"三条新断言（浏览器自检需人在普通终端跑一次）。
> **范围**：家居场景页的**信息分层**，以及把产品形态（主人手机上的 App）做成右栏可收起的 iPhone 机模。
> **不在本阶段**：真实 App、后端、推送、多猫个体归属。

## 1. 四条反馈与对应的改动

| 反馈 | 改动 |
|---|---|
| ① 右栏那份"项目情况说明"不该占主界面 | **居家资源清单**从右栏移出，成为独立页面 `#/resources`（渲染代码抽到 `ui/resource-list.ts`，3D 房间与清单继续共用同一份布局数据） |
| ② 左栏太满 | 左栏只留**操作**：模式、突发演示、机位；**图层与画质**（含 6 个开关与工程统计行）收进 `<details>`；首屏提示卡片并入"猫的行为"面板的说明行 |
| ③ 生理读数要实时出现在 App 模拟视图里 | App 预览的**实时**页签按场景演示时刻取会话读数：心率 / 呼吸 / 体表温 + 当前活动 + 有效性标记，0.5 s 节流刷新，时钟逐帧走字 |
| ④ App 模拟视图放右栏、可收起、做成 iPhone、含基本功能 | 右栏 `AppPhone`：CSS 画的 iPhone（圆角机身 + 灵动岛 + Home 指示条），四个页签**实时 / 事件流 / 漂移 / 档案**，标题条上的按钮收起展开 |

## 2. 新布局

```
┌───────────────────────────────────────────────────────────────────────┐
│ 顶栏：项圈 · 伴侣视角        家居场景 · 生理读数 · 居家资源 · 工程自检      │
├──────────────┬────────────────────────────────────┬───────────────────┤
│ 左栏（操作）   │                                    │ 右栏（App 预览）    │
│               │                                    │ ┌───────────────┐ │
│ 猫的行为       │            3D 样板间               │ │ App 预览  [收起]│ │
│  · 自主/手动   │        （只由场景承担"数据从哪来"）    │ │ ▢ iPhone      │ │
│  · 突发演示    │                                    │ │  实时/事件/漂移 │ │
│ 机位          │                                    │ │  /档案        │ │
│ 图层与画质 ▾   │                                    │ └───────────────┘ │
└──────────────┴────────────────────────────────────┴───────────────────┘
```

三条站位纪律（这一节是重点，改动它之前先读）：

1. **左栏只放"操作"**。任何只读的信息都不属于左栏——否则操作项会被信息挤走，而演示时最常用的只有模式与突发。
2. **右栏只放 App 预览**。它承载产品形态，是这一页的第二主角，不能与清单、统计共用空间。
3. **报告类内容独立成页**。居家资源清单是"一份可核查报告"，它的读者、阅读时长与场景页完全不同。

## 3. 单一时间线（本次改动里最容易踩坏的一处）

App 预览要显示"此刻的读数"，就必须让**画面**与**读数**取自同一条时间线。
而此前突发演示是这样工作的：`HomeScene.triggerIncident()` 在**场景内部**重建一条带注入突发的时间线。
于是会有两条时间线——画面跑的新时间线，与会话数据（读数、事件流）的旧时间线。手机一挂上去，这个缝立刻显形：

> 猫在抽搐（画面），手机上的心率却还是抽搐前的值。

**修法**：把"重建时间线"这件事上移给**持有会话的一侧**：

```ts
// screens/home.ts —— 唯一时间线
const atS = scene.simTimeS();
session = buildSession([{ atS, kind }]);            // 重建**带注入突发的会话**
scene.applyTimeline(session.behaviorTimeline, atS - 1);  // 场景换成同一条时间线
phone.setSession(session, false);                    // 读数、事件流跟着换
```

配套改动：
- `BehaviorStatus` 新增 `timeS`（会话内秒）。`hourOfDay` 被 24 取模过，**无法**反推会话内绝对时刻；
  手机按 `timeS` 去查采样点，画面与读数才落在同一时刻。
- `HomeScene` 新增 `applyTimeline(timeline, startAtS)` 与 `simTimeS()`，并**复用同一个 `onBehaviorStatus` 字段**
  ——第三阶段已经在这条纪律上踩过一次（见 stage2 §6.7），不允许再出现第二份回调。
- 开场注入（`?incident=`）也改走会话：注入发生在会话里，因此一进场画面与读数就是一致的。
- `?debug=1&auto=1` 的自检动作 `incident` 同样走这条路径，所以自动验证覆盖的是**按钮真正走的那条代码**。

> `HomeScene.triggerIncident()` 保留为场景级兜底（不删，它的注释记录了接线纪律），但应用界面不再使用它。

## 4. App 预览的四个页签

| 页签 | 显示什么 | 数据来源 | 诚实边界 |
|---|---|---|---|
| **实时** | 它现在在做什么 / 在哪（含突发演示名）；心率、呼吸、体表温三行读数 | 场景状态 + 会话采样点（按 `timeS` 查） | 无效窗口**划线显示**并给出失效原因；常驻 `VITALS_BOUNDARY_NOTE` |
| **事件流** | 事件类型汇总（抓挠 ×N、发声 ×N…）+ 截止当前时刻的事件列表（时间 · 事件名 · 强度） | `session.events` | 只描述"发生了一次什么"，不判断原因 |
| **漂移** | 心率 / 呼吸 / 活动量 / 发声次数：前半段基线 vs 后半段近期，给严重度徽章与效应量 | `core.detectDrifts`（200 次置换） | 明说只描述"相对这只猫自己前半段基线"的变化 |
| **档案** | 物种 / 品种 / 年龄段 / 体型档 / 体重肩高 / 项圈重量预算 | `core` 的 `ageBandOf` / `sizeClassOf` / `collarBudgetOf` | 说明档案驱动的是"这只猫自己的基线"，不是种群平均值 |

**为什么要有"事件流"与"漂移"这两页**：它们本来就是项目的两条主线（`AGENTS.md` §1 的 ② 与 ③）。
把主线放进机模里，观众看到的就不再是"一个 3D 房间"，而是"**主人手机上会看到什么**"。

**词汇纪律**：活动名、事件名、突发名、边界句全部来自 `@camp/core`。
本次为此在 core 里补了 `SIM_EVENT_LABELS` / `simEventLabel()`——事件名在此之前**没有任何中文名**，
若在界面里就地写一套，就会出现"同一件事在房间标签里叫抓挠、在手机里叫 scratch"。

## 5. 自检（需人在普通终端跑一次）

```bash
node scripts/dev-server.mjs
chrome --headless=new --use-angle=swiftshader --enable-unsafe-swiftshader \
       --virtual-time-budget=40000 --window-size=1280,860 \
       "http://127.0.0.1:5273/?debug=1&auto=1"
node scripts/smoke-scene.mjs
```

`auto` 序列现在会依次：切激动 → 切平静 → **收起/展开 App** → 注入抽搐 → 打开项圈与无干涉区 →
**切事件流 / 漂移 / 档案 / 回实时** → 结束后再回传一次。`smoke-scene.mjs` 新增断言：

| 断言 | 防的是什么故障 |
|---|---|
| App 预览已挂载、默认展开 | 右栏根本没挂上（最容易被忽略：不报错、只是什么都没有） |
| 页签可以切换（≥3 种） | 页签点了没反应 |
| 读数是数值而不是占位 | 手机在显示 `—` |
| **突发期间呼吸读数被标为不可用** | 把坏值当读数照抄（第三阶段的读数有效性在界面上失效） |
| 事件流页签渲染出事件行 | 事件流是空的 |
| 项圈部件数 = 5、无干涉区可见 | 第三阶段的形态可视化没挂上 |

## 6. 已知限制

1. **窄屏（≤900px）默认收起 App 预览**：手机上场景本身已经占满屏，机模会挡住 3D。展开后它贴在右下角。
2. **漂移页只有 200 次置换**（CLI 与测试用 1000）：手机预览要瞬时出结果，牺牲一点 p 值精度。界面不展示 p 值。
3. **机模是 CSS 画的**，不含真实 App 的导航栈、手势与推送——它演示的是**信息结构**，不是交互原型。
4. **会话是 24 小时、倍率 20×**：所以一次演示走完约 72 分钟；手机上的时间也是这个压缩时钟，
   界面已注明"演示倍率 20×"，不把压缩时钟说成真实时间。
5. 场景页仍**不接** `?scenario=vet-visit` 以外的场景切换按钮（诊室情境的对照只在生理读数页提供）。
